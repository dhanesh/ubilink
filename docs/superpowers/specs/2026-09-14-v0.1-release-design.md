# Ubilink v0.1.0 — first public release: design

**Status:** approved in design review (all five sections), 2026-09-14 · **Owner:** @dhanesh
**Supersedes for release work:** `docs/RUNBOOK-ci-signing.md` (folded into a new release runbook)

## 1. Goal and scope

Ship Ubilink **v0.1.0** as a **Developer ID–signed, Apple-notarized, universal
(Apple silicon + Intel) `.dmg`** on GitHub Releases, built reproducibly in CI, with
honest docs.

**In v0.1.0:** capture (Cmd+Shift+K), link graph + browser (Cmd+Shift+L), settings
(Cmd+Shift+,), built-in and custom app adapters, graph export/import, permission
onboarding, plus all hardening merged in #1–#15.

**Explicitly not in v0.1.0 (deferred to the release that wires the plugin runtime):**
the plugin sandbox runtime in the app (the sandbox/broker/registry stay
developer-facing, labelled "coming next"), a non-macOS OS sandbox, a plugin memory
cap, an auto-updater, file logging / crash reporting.

**Decisions taken in review**

| Decision | Choice |
|---|---|
| Distribution | Signed + notarized DMG on GitHub Releases |
| Plugin runtime | Not shipped in v0.1.0 |
| Apple credentials | Account exists; Developer ID cert + API key not yet created → pipeline has a dry-run mode |
| Architectures | Universal (arm64 + x86_64) |
| Packaging approach | **A:** extend `scripts/bundle-macos.sh` (Apple-native tools only), not the Tauri bundler |
| Version | 0.1.0; no auto-updater |

## 2. Sub-projects and order

1. **Version source + release docs** (§5) — first; packaging and the pipeline read the version.
2. **Packaging** (§3) — needs §5's version source.
3. **Release pipeline** (§4) — calls the packaging script.
4. **Polish & cleanups** (§6) — independent, in parallel.
5. **Spec hygiene (`.manifold`)** (§6) — independent, in parallel.

**Maintainer actions (not code), documented in the release runbook:** create the
Developer ID Application certificate and an App Store Connect API key; create the
GitHub `release` environment (required reviewers; deployments limited to `main` + `v*`
tags) with the Apple secrets and `UBILINK_SIGNING_KEY`; add a `v*` tag ruleset; enable
GitHub private vulnerability reporting.

## 3. Packaging — `scripts/bundle-macos.sh`

One script, three modes, used by `make` and CI:

| Mode | Invoked by | Signing | Output |
|---|---|---|---|
| `dev` (default) | `make bundle` | Self-signed "Ubilink Self-Signed" identity (as today, keeps TCC grants stable across rebuilds) | `Ubilink.app` only |
| `dry-run` | `make dist` without Apple credentials | Ad-hoc, hardened runtime | `Ubilink-<ver>-universal-UNNOTARIZED.dmg` |
| `release` | `make dist` with all Apple credentials | Developer ID, hardened runtime, secure timestamp; notarized + stapled | `Ubilink-<ver>-universal.dmg` |

**Stages**

1. **Version** from `scripts/version.sh` (§5). Nothing hard-coded.
2. **Universal build:** `cargo build --release --locked` for `aarch64-apple-darwin` and
   `x86_64-apple-darwin` (both listed in `rust-toolchain.toml` `targets`), then
   `lipo -create`.
3. **Assemble `Ubilink.app`:** Info.plist as today (identifier `org.dhanesh.ubilink`
   unchanged so it remains the same app to macOS; `CFBundleName`/`DisplayName` Ubilink;
   executable `ubilink`; `NSAppleEventsUsageDescription`; `LSMinimumSystemVersion`
   10.15), `.icns` from `desktop/icons/icon.png`.
4. **Entitlements:** new `desktop/Ubilink.entitlements` containing only
   `com.apple.security.automation.apple-events` = true. Every capture sends Apple Events
   via `osascript`, which a hardened-runtime app cannot do without it. No JIT, no
   unsigned-executable-memory, no App Sandbox (web content runs in WebKit's own
   Apple-signed processes).
5. **Sign:** `codesign --force --options runtime --timestamp --entitlements <file>
   --sign "$APPLE_SIGNING_IDENTITY"` (ad-hoc `-` in dry-run, keeping `--options
   runtime` and the entitlements so dry-run exercises the same shape). In CI the `.p12`
   is imported into a temporary keychain that is deleted when the step ends.
6. **Notarize the app (release mode):** `ditto -c -k --keepParent` → `xcrun notarytool
   submit --wait` with the App Store Connect API key → `xcrun stapler staple
   Ubilink.app`, so a copy in /Applications passes Gatekeeper offline.
7. **DMG:** `hdiutil create -format UDZO` with `Ubilink.app` and an `/Applications`
   symlink; sign the DMG; notarize and staple it (release mode).
8. **Verify (script fails on any miss):**
   - `lipo -archs` shows both `arm64` and `x86_64`;
   - `codesign --verify --deep --strict --verbose=2` passes;
   - the embedded entitlements are exactly the Apple Events entitlement;
   - the Info.plist carries the §5 version and the Apple Events usage string;
   - `hdiutil verify` passes;
   - release mode only: `spctl -a -t exec -vv` accepts the app, and `xcrun stapler validate` passes on both the app and the DMG.

**Credentials (environment only, never in the repo):** `APPLE_SIGNING_IDENTITY`,
`APPLE_CERTIFICATE_P12_BASE64`, `APPLE_CERTIFICATE_PASSWORD`, `APPLE_API_KEY_ID`,
`APPLE_API_ISSUER`, `APPLE_API_KEY_P8_BASE64`.

**Safety rules**
- Release mode refuses to run with a *partial* credential set (all six or none).
- The mode is chosen by the pipeline (§4): a final tag (`vX.Y.Z`) **fails** without
  credentials; an rc tag (`vX.Y.Z-rc.N`) or a manual run may produce the UNNOTARIZED
  dry-run DMG. An un-notarized build can never ship as a final release.

**Note:** TCC grants are keyed to the signing identity, so users who granted
permissions to a self-signed dev build re-grant once for the Developer ID build
(documented in README and CHANGELOG). The dev bundle is also renamed from
`ubilink.app` to `Ubilink.app` (matching the release bundle), so developers re-grant
their dev build once as well.

## 4. Release pipeline — `.github/workflows/release.yml` (+ `ci.yml`)

**Triggers:** `v*` tags, or a manual run from `main` (unchanged from #10). The tag's
version must match `scripts/version.sh` (`v0.1.0` or `v0.1.0-rc.N` for 0.1.0),
otherwise the run fails. A manual run builds and uploads artifacts only; it never
creates a release.

**Jobs**

| Job | Needs | Does | Secrets / permissions |
|---|---|---|---|
| `verify` | — | `make verify LOCKED=--locked` (macOS) | `contents: read` |
| `build-app` | verify | Choose mode (all Apple secrets → release; rc tag or manual → dry-run; else fail) → `make dist` → verify → upload the DMG artifact. No build cache (a poisoned cache can't reach the signer). `timeout-minutes: 120`. | `release` environment; Apple secrets only in the packaging step |
| `sign-integrations` | verify | Existing ed25519 sign + self-verify of the integration bundle | `release` environment; `UBILINK_SIGNING_KEY` |
| `draft-release` | build-app, sign-integrations | Download artifacts → `SHA256SUMS` → **draft** GitHub Release with notes from the `CHANGELOG.md` section for this version; attach DMG, `SHA256SUMS`, signed bundle; rc tags marked prerelease | **only** job with `contents: write` |

- Uses the preinstalled `gh` CLI; **no new third-party actions**. All `uses:` remain
  pinned to commit SHAs (#10).
- Nothing auto-publishes: the maintainer reviews the draft, runs the RC checklist, then
  publishes.
- **`ci.yml`:** a `package-dry-run` job (macOS) runs `make dist` in dry-run mode on PRs
  that touch `scripts/**`, `desktop/**`, `Makefile`, `rust-toolchain.toml` or
  `.github/workflows/**`.

**Runbook:** new `docs/RUNBOOK-release.md` (supersedes `RUNBOOK-ci-signing.md`):
creating the Developer ID cert and API key, base64-encoding them, the GitHub
environment + secrets + tag ruleset, enabling private vulnerability reporting, bumping
the version, cutting an rc, the **RC checklist**, publishing, and handling a
notarization rejection (`xcrun notarytool log <id>`).

**RC checklist (manual, on a clean Apple-silicon Mac and a clean Intel Mac):**
download the DMG from the draft; `shasum -a 256 -c SHA256SUMS`; open the DMG and drag
to Applications with no Gatekeeper warning; launch; Automation + Accessibility prompts
appear with the right text; a capture from Safari and from Finder works; export/import
works; Settings shows the version.

## 5. Version source of truth and release docs

- **Source:** `desktop/Cargo.toml` `version`. `scripts/version.sh` prints it.
- **Fewer copies:** remove `version` from `desktop/tauri.conf.json` (Tauri 2 falls back
  to the Cargo package version); delete the obsolete `src-tauri/tauri.conf.json` (§6).
- **Consistency check (`make verify-version`, part of `make verify`):** fails when
  `src-tauri/Cargo.toml` or `registry/Cargo.toml` differ from the desktop version, or
  when `CHANGELOG.md` has no `## [<version>]` section.
- **Bump to 0.1.0** in all three crates and their `Cargo.lock` files. Bumping is
  documented in the runbook; no bump tool.
- **`CHANGELOG.md`** (Keep a Changelog): `## [0.1.0]` with Added (features),
  Security (hardening #1–#15, one line each), Known limitations (macOS only; no plugin
  runtime; no auto-update; one-time permission re-grant from dev builds). The release
  job uses this section as release notes.
- **`SECURITY.md`:** supported versions (latest release); report privately via GitHub
  private vulnerability reporting; pointer to README "Security model", D14 and D16.
- **README:** *Install* (download from Releases, verify with `shasum -a 256`, drag to
  Applications), *First run* (Automation + Accessibility prompts, one-time re-grant),
  *Requirements* (macOS 10.15+, Apple silicon or Intel), *Uninstall* (delete the app and
  `~/Library/Application Support/org.dhanesh.ubilink`), link to build-from-source.

## 6. Polish, cleanups and spec hygiene

- Delete `src-tauri/tauri.conf.json` (skeleton; confirm nothing references it).
- `make fmt` / `make clean` include the desktop crate.
- `run-desktop` help text: Cmd (not Cmd/Ctrl) — only `SUPER` is registered.
- Rename the stale `bear_spec_urlencodes_the_title_into_the_scheme` test.
- D10: replace "durable storage ENV-blocked" with a pointer to #14's persistence.
- UI/docs make no plugin-runtime promises; it is labelled "coming next".
- **Settings shows the app version** (e.g. "Ubilink 0.1.0"), from Tauri's app version
  (which comes from `desktop/Cargo.toml`).
- **`.manifold`:** run `manifold verify` + `manifold drift`; refresh stale evidence
  hashes; record O2 honestly as not satisfied (no in-app capabilities view); reconcile
  loop-state figures. No new constraints.

## 7. Testing and acceptance

**Automated**
- `make verify` includes `verify-version`.
- `package-dry-run` CI job produces the UNNOTARIZED universal DMG and its verify stage
  passes (archs, signature, entitlements, plist, `hdiutil verify`).
- `scripts/test-bundle-modes.sh`, run by `package-dry-run`: with fake environments and
  a stubbed `codesign`/`notarytool` on `PATH`, asserts that no credentials → dry-run,
  all six → release, any partial set → refusal (non-zero exit, clear message), and that
  the pipeline's mode rule fails a final tag without credentials.

**Definition of done**
1. Tag `v0.1.0-rc.1` → a **draft** prerelease with the UNNOTARIZED universal DMG,
   `SHA256SUMS` and the signed integration bundle, before Apple credentials exist.
2. After the maintainer adds credentials, `v0.1.0-rc.N` → a notarized, stapled DMG;
   `spctl` and `stapler validate` pass in CI.
3. The RC checklist passes on a clean Apple-silicon Mac and a clean Intel Mac.
4. Tag `v0.1.0` → draft release; the maintainer publishes it.
5. A final tag without credentials fails the pipeline.

## 8. Risks

- **Entitlement sufficiency:** if Apple Events still fail under the hardened runtime,
  the RC checklist catches it (capture from Safari/Finder); fix before `v0.1.0`.
- **Notarization rejection:** handled via `notarytool log`; the runbook covers it.
- **Universal build time:** cold, uncached, two targets; `timeout-minutes: 120`.
- **TCC re-grant** for existing dev users: documented.
- **Bear adapter** reads Bear's Group Container via `sqlite3`; may add a privacy prompt;
  not a notarization blocker; it is disableable.
